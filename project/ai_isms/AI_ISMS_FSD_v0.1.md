## 1. 공통 사양

### 1.1 역할-기능 권한 매트릭스 `[보완: PRD 4.2에 역할만 있고 기능 매핑 없음]`

C=생성, R=조회, U=수정, D=삭제, A=승인

| 기능 영역 | 시스템 관리자 | 보안 관리자 | 부서 담당자 | 검토자 | 감사자 | 경영진 | 외부 컨설턴트 |
|---|---|---|---|---|---|---|---|
| 사용자/권한 | CRUD | R | - | - | R | - | - |
| 심사 프로젝트 | CRUD | CRUD | R(배정분) | R | R | R | R(허용 조직) |
| 기준 관리 | CRUD | CRU | R | R | R | - | R |
| 체크리스트 점검 | R | CRU | CRU(배정분) | R+A | R | - | CRU(허용 범위) |
| 증적 | R | CRUD | CRU(배정분) | R+A | R | - | CRU(허용 범위) |
| 미흡사항/개선계획 | R | CRUD | CRU(배정분) | R+A | R | R(요약) | CRU(허용 범위) |
| AI 분석 | R | CR | CR(배정 범위) | CR+A | R | R(요약) | CR(허용 범위) |
| 보고서 | R | CR | R | R+A | R | R(요약) | CR(허용 범위) |
| 감사로그 | R | R | - | - | R | - | - |
| 시스템 설정 | CRUD | - | - | - | - | - | - |

- 모든 권한은 RBAC(FR-SEC-01) + 부서/문서/기밀등급 필터(FR-SEC-02~04)의 교집합으로 평가한다.
- 외부 컨설턴트는 허용된 조직·프로젝트 범위 외 데이터에 어떤 화면·API·AI 검색으로도 접근할 수 없다(NFR-SCL-05).

### 1.2 공통 상태 모델

#### 워크플로우 상태 전이 (점검·증적·개선계획·보고서 공통, PRD 7.4/7.16)

```text
작성중 --제출--> 검토중 --승인--> 승인완료
  ^                |
  +-----반려-------+        (반려 시 사유 필수 입력, 작성중으로 복귀)
승인완료 --변경 발생--> 작성중(새 버전, 기존 승인본은 이력 보존, NFR-AUD-04)
```

#### 증적 상태 전이 `[보완: PRD 7.5는 상태 6종만 나열, 전이 규칙 없음]`

| 현재 상태 | 이벤트 | 다음 상태 | 권한 | 색인(RAG) 동작 |
|---|---|---|---|---|
| 등록 | 검토 요청 | 검토중 | 담당자 | 미반영 |
| 검토중 | 승인 | 승인 | 검토자 | 색인 반영(FR-EVD-10) |
| 검토중 | 반려(사유 필수) | 반려 | 검토자 | 미반영 |
| 승인 | 만료일 도래 | 만료 | 시스템(배치) | 색인 무효화(FR-EVD-11) |
| 승인 | 신규 버전 업로드 | 교체 필요→승인(신규) | 담당자+검토자 | 구버전 무효화, 신버전 반영 |
| 반려 | 재업로드 | 등록 | 담당자 | - |

### 1.3 파일 업로드 공통 규칙 `[보완: PRD에 미정의]`

1. 허용 형식 화이트리스트: pdf, docx, xlsx, pptx, txt, md, csv, png, jpg, eml, zip(내부 재검사)
2. 단일 파일 100MB, 요청당 10파일 기본 한도(시스템 설정으로 조정 가능)
3. 업로드 시 악성코드 검사(AV 스캔)를 통과해야 저장된다. 실패 시 격리 및 감사로그 기록
4. 실행 파일(exe, sh, bat 등)은 압축 내부 포함 시에도 차단
5. 파일은 저장 시 암호화(NFR-과 FR-SEC-12), 원본 해시(SHA-256)를 메타데이터로 보존

### 1.4 공통 오류 응답

| 코드 | 의미 | 처리 |
|---|---|---|
| E-AUTH-401 | 미인증 | 로그인 화면 유도 |
| E-AUTH-403 | 권한 없음 | 사유 미노출(존재 여부 비공개), 감사로그 기록 |
| E-VAL-4xx | 입력 검증 실패 | 필드 단위 오류 메시지 |
| E-FILE-4xx | 파일 형식/크기/AV 실패 | 거부 사유 표시 |
| E-AI-NOEVID | AI 근거 부족 | 판단불가 응답 포맷으로 전환(2.7절) |
| E-IDX-5xx | 색인 실패 | 재시도 큐 등록(NFR-AVL-04), 관리자 알림 |

### 1.5 감사로그 공통 규칙 (FR-LOG-01~16)

- 모든 쓰기 행위와 1.1절 A(승인) 행위는 행위자, 시각(UTC+9), 대상 객체 ID, 변경 전/후 값을 기록한다.
- 로그는 append-only로 저장하고 해시체인으로 위변조를 검증한다(FR-SEC-13).
- AI 질문/응답/참조문서 로그(FR-LOG-09~11)는 기밀등급 "내부 이상"으로 분류하고 1.1절 감사로그 권한자만 조회한다(FR-SEC-15).

## 2. MVP 기능 명세

### 2.1 사용자 및 권한 관리 (FS-USR) `[보완: PRD 7장에 사용자 관리 기능 절 없음 — 5.1/17.1의 P0 항목을 신규 상세화]`

|---|---|---|---|
| FS-USR-01 | 5.1-10, 17.1-1 | 사용자 등록/초대 | 이메일 초대, 최초 로그인 시 비밀번호 설정 강제 |
| FS-USR-02 | 4.2 | 역할 부여 | 4.2의 7개 역할 중 1개 이상, 역할 변경은 시스템 관리자만 |
| FS-USR-03 | FR-SEC-02 | 부서 배정 | 부서별 접근제어의 기준 값 |

| FS-USR-05 | FR-SEC-07 | 세션 관리 | 유휴 30분 만료(설정 가능), 동시 세션 수 제한 |

| FS-USR-08 | FR-LOG-03,04 | 계정/권한 변경 로깅 | 변경 전후 값 포함 |

수용 기준: 권한 없는 계정의 화면·API·AI 검색 접근이 모두 차단된다(MVP 완료 기준 11).

### 2.2 심사 프로젝트 및 워크플로우 내비게이션 (FS-PRJ ← FR-PRJ-01~09)

| FS ID | PRD ID | 기능 | 처리 규칙 |
|---|---|---|---|
| FS-PRJ-01 | FR-PRJ-01 | 프로젝트 생성 | 심사 유형(7.20의 11종), 명칭, 목표 심사일 입력. 생성 직후 프로파일 적용 |
| FS-PRJ-02 | FR-PRJ-02 | 프로파일 적용 | assessment_types에서 기준 버전, 단계 구성, 증적·보고서 템플릿, 메뉴 구성을 로드. 체크리스트 인스턴스는 FS-CHK-01을 호출하여 생성 `[보완: 7.4와 7.20의 생성 주체 중복을 호출 관계로 정리]` |
| FS-PRJ-03 | FR-PRJ-03 | 스테퍼 표시 | 진행률 = 단계별 가중치 × 단계 완료율의 합. 단계 완료율 산식: 범위 설정=필수 항목 입력률, 자체 점검=항목 점검 완료율, 증적 보완=필수 증적 등록률, 미흡사항 조치=조치 완료율, 보고서=필수 보고서 승인률 `[보완: PRD에 산식 없음]` |
| FS-PRJ-04 | FR-PRJ-04 | 단계 바로가기 | 현재 단계의 미완료 항목 수를 집계해 해당 화면에 필터 적용 상태로 이동 |
| FS-PRJ-05 | FR-PRJ-05 | 이전 결과 이어받기 | 직전 프로젝트의 점검 결과·미흡사항을 스냅샷 복사(수정 가능), 증적은 연결만 복사 |
| FS-PRJ-06 | FR-PRJ-06 | 병행 운영 | 프로젝트 간 점검 결과 완전 분리, 동일 통제항목의 타 프로젝트 결과는 참고 정보로만 표시 |
| FS-PRJ-07 | FR-PRJ-07 | 증적 공유 | 증적-점검항목 연결은 (프로젝트, 점검항목, 증적) 3원 관계로 저장 |
| FS-PRJ-08 | FR-PRJ-08 | 상태 관리 | 준비중→진행중→심사중→완료, 보류는 어느 상태에서든 가능 |
| FS-PRJ-09 | FR-PRJ-09 | 프로파일 관리 | 시스템 관리자가 데이터로 구성, 프로파일은 기준 버전 FK 보유 |

수용 기준: 첫 화면에서 심사 유형 선택→프로젝트 생성→스테퍼 표시까지 추가 설정 없이 동작한다(MVP 완료 기준 12, 13). 스테퍼는 단계 이동을 차단하지 않는다(7.20 준수사항 1).

### 2.3 조직 및 인증 범위 관리 (FS-ORG ← FR-ORG-01~10)

- FR-ORG-01~09를 등록/수정/이력 CRUD로 구현한다. 필수 데이터는 PRD 7.2의 11개 필드.
- FS-ORG-10 (FR-ORG-10): 인증 범위 변경 시 승인자·변경일·사유를 이력으로 저장하고, 연결된 프로젝트에 "범위 변경됨" 배지를 표시한다.
- `[보완]` 계층 구조 정의: 조직(1) ─ 부서(N) ─ 서비스(N) ─ 시스템(N), 시스템은 자산(Phase 2)과 1:N. PRD에 계층 관계 미정의.

### 2.6 증적 관리 (FS-EVD ← FR-EVD-01~13)

- FS-EVD-01 (FR-EVD-01,02): 업로드(1.3절 규칙) 후 점검항목·필요 증적 유형에 연결. 메타데이터: PRD 7.6의 15개 필수 항목.
- FS-EVD-02 (FR-EVD-03): 버전 관리 — 동일 증적의 재업로드는 새 버전, 구버전은 이력 보존.
- FS-EVD-03 (FR-EVD-04): 만료일 관리 — 기본값은 필요 증적 정의(FS-STD-06)의 권장 주기에서 계산, 담당자 수정 가능 `[보완: PRD에 만료일 산정 주체 미정의]`. 만료 30/7일 전 알림(FS-NTF-03).
- FS-EVD-04 (FR-EVD-05,06): 검토·승인·반려는 1.2절 증적 상태 전이를 따른다.
- FS-EVD-05 (FR-EVD-07,08): 기밀등급(공개/내부/기밀/개인정보 포함 — 8.4 매트릭스와 동일 체계) 및 접근권한 지정. 기밀등급은 외부 LLM 전송 매트릭스(NFR-SEC-07)의 입력 값.
- FS-EVD-06 (FR-EVD-09,10,11): 승인 시 텍스트 추출(OCR 포함)→FS-RAG 파이프라인 인입. 만료·반려·교체 시 색인 무효화 이벤트 발행.
- FS-EVD-07 (FR-EVD-12): 중복 탐지 — 파일 해시 동일 시 즉시, 텍스트 유사도 높음(임계값 설정)은 후보 표시.
- FS-EVD-08 (FR-EVD-13): 동일 항목에 다수 증적 연결 시 최신 승인본 우선 정렬.

수용 기준: 업로드→연결→승인→RAG 반영이 한 흐름으로 동작하고(MVP 완료 기준 3), 반려·만료 증적이 AI 검색 결과에 나타나지 않는다.

### 2.7 RAG 지식베이스 및 AI 분석 (FS-RAG ← FR-RAG-01~15, FS-AIA ← FR-AIA-01~11)

#### 색인 파이프라인 (FS-RAG-01, PRD 9.1의 18단계 구현)

수집→파싱→텍스트 추출→PII 탐지·마스킹→청크 분할(기본 800자, 오버랩 100자, 설정 가능 `[보완]`)→메타데이터(임베딩 모델 버전 포함)→임베딩→벡터 저장→키워드 인덱싱. 실패 단계는 재시도 큐(최대 3회) 후 관리자 알림.

#### 검색 (FS-RAG-02, FR-RAG-08~10,12~14)

1. 권한 사전 필터(조직, 프로젝트, 부서, 기밀등급, 문서 접근권한)를 벡터·키워드 질의 모두에 적용
2. 하이브리드 검색(벡터 + BM25) 후 Re-ranking, 상위 k(기본 8) 청크 선택
3. 기본 옵션: 만료 문서 제외=ON, 최신 버전 우선=ON, 문서 버전 지정 검색은 감사자·검토자용 고급 옵션
4. 검색 결과 0건 또는 관련도 임계값 미만이면 E-AI-NOEVID로 분기, retrieval_logs에 실패 기록(FR-RAG-15)

#### AI 응답 (FS-AIA-01~03)

- FS-AIA-01: 응답은 PRD 7.7의 11개 필드 포맷(판단 결과~담당자 검토 필요 여부)을 JSON 스키마로 강제하고 화면에 구조화 표시.
- FS-AIA-02: 분석 요청은 비동기 처리 `[보완: PRD 미정의]` — 큐 등록 후 화면에 진행 상태 표시, 완료 시 알림. 첫 토큰 5초/완료 15초 목표(NFR-PER-03)는 대화형 질문에 적용, 일괄 분석은 배치.
- FS-AIA-03 판단불가 처리: 사유 코드(근거 미검색/권한 부족/증적 만료/증적 상충) 저장, 부족 증적의 원클릭 필요 증적 등록과 담당자 보완 요청(7.7 후속 처리 1~4).
- FS-AIA-04 신뢰도: 9.3의 규칙 기반 산정(LLM 자가 보고 금지). 낮음 응답의 판단불가 전환 임계값은 시스템 설정.
- FS-AIA-05 인용 저장: 응답에 사용된 청크 ID·문서 ID·버전을 ai_citation_logs에 저장 — 품질 지표 13.2-1의 측정 원천.
- FS-AIA-06 사용자 액션: 승인/수정/반려, 개선계획 전환(FS-PLN-01), 보고서 문장 전환(FS-RPT-03).

수용 기준: 모든 판단 제시 응답에 참조 근거가 표시되고(MVP 완료 기준 5), 근거 부족 시 판단불가로 응답하며(기준 6), 권한 밖 문서가 근거에 포함되지 않는다(기준 11).
